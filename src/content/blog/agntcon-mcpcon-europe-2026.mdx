## AGNTCon + MCPCon Europe 2026: Two Days of Real Agentic AI at RAI Amsterdam

**Day 1 recap** — 2,000+ attendees, keynotes from the co-creator of MCP, and the data that shows agentic AI has already crossed into production.

Yesterday I attended **AGNTCon + MCPCon Europe** at RAI Amsterdam — the Linux Foundation's flagship conference on agentic AI and the Model Context Protocol. The tagline says *"Where the agent stack is being built"* and after walking the floor, I can confirm: this is exactly the right place to be if you want to see how the agentic stack is taking shape.

## The Scene: RAI Amsterdam, September 17-18

The event occupies the main auditorium at RAI Amsterdam, complete with professional video cameras, tiered blue theater seating, and the kind of dramatic purple-and-blue lighting that makes every photo look like it belongs on a conference highlight reel. The crowd of **2,000+ attendees** represents the full spectrum of the agentic AI ecosystem: open source maintainers, enterprise platform engineers, researchers, and developer advocates from companies like Microsoft, Elastic, AWS, Anthropic, GitHub, and Hugging Face.

The event is co-hosted by the **Agentic AI Foundation**, with production support from the Linux Foundation. As a media partner, I was on the ground capturing the key moments — from the opening keynotes to the panel discussions to the hallway conversations where the real insights live.

## Keynote 1: Welcome — Angie Jones, VP at Agentic AI Foundation

**9:00 AM | Auditorium (Ground Floor)**

The morning kicked off with **Angie Jones**, Vice President of Developer Experience at the Agentic AI Foundation. Angie — a master inventor with 27 patents and a renowned international keynote speaker — set the tone for the two days ahead.

Her message was clear: the era of "AI agents as a future technology" is over. The era of **"AI agents as a production technology"** has begun. Every decision the conference would return to — from security to observability to interoperability — was framed through the lens of production readiness.

## Keynote 2: MCP and the Era of Connectivity — David Soria Parra, Co-creator of MCP, Anthropic

**9:18 AM | Auditorium (Ground Floor)**

Fresh off the welcome, **David Soria Parra** — Member of Technical Staff at Anthropic and co-creator of the Model Context Protocol — took the stage for what was arguably the most anticipated session of Day 1.

David's background is a fascinating primer for anyone building on top of MCP: former core developer for PHP, contributor to Git and Mercurial, former engineering leader at Meta/Facebook, entrepreneur-in-residence at Sutter Hill Ventures, and now at Anthropic driving MCP forward. His talk — *"MCP and the Era of Connectivity"* — was a masterclass in how a protocol designed to solve a narrow problem (connecting AI assistants to external data) evolved into the most adopted standard in the agentic stack.

The key announcement: **MCP moves to a stateless core**, with a new extensions framework, authorization changes, and a clear migration path for existing clients and servers. This is the kind of evolution that will define agentic AI infrastructure for years to come.

## Breakout: MCP Doesn't Have a Context Problem — Sam Morrow, GitHub

**12:35 PM | Emerald Room (1st Floor)**

Of the morning breakouts, this was the one I'd circled. **Sam Morrow** from GitHub took on the most common complaint about MCP. His [session abstract](https://agntconmcpconeu26.sched.com/event/2RB8t/mcp-doesnt-have-a-context-problem-sam-morrow-github) sums it up: critics say MCP dumps every tool into the system prompt and every response straight back to the model, and that CLIs and agent skills are more efficient. In his view they're right about the symptoms and wrong about the cause. The real gap is that hardly anyone had done serious context engineering on top of MCP.

![Slide titled Hot Takes collecting critical quotes about MCP tool descriptions filling the context window, attributed to Peter Steinberger, Simon Willison and others, with Sam Morrow at the lectern](/blog/events/agntcon-mcpcon-europe-2026/sam-morrow-mcp-context-hot-takes.jpg)

*The "Hot Takes" slide: quotes from Peter Steinberger, Simon Willison and others saying that MCP tool descriptions eat the context window.*

He opened with a **"Hot Takes"** slide that collected those criticisms. Peter Steinberger, Simon Willison and others each made the same point: tool descriptions take up valuable context before the agent has done anything. According to the abstract, the rest of the talk used his own agent harness, **mcpi**, to show three ways to discover tools progressively over MCP, each paying only for the context tokens it needs. The main one was **skills over MCP**: a skill describes the tool surface and switches tools on only when the skill is invoked. MCP CLIs and **code mode** were the other two.

![Bar chart titled Merged PRs by author for the github/github-mcp-server repository, generated live during the talk, with Sam Morrow looking at the screen](/blog/events/agntcon-mcpcon-europe-2026/sam-morrow-merged-prs-by-author.jpg)

*The live demo's output: a "Merged PRs by author" chart for `github/github-mcp-server`, built by an agent through the GitHub MCP server.*

The demo was the proof. The agent pulled the merged pull request history of `github/github-mcp-server` and rendered it as an animated "race" chart (`pr_race.gif`). In my clip of the wrap-up, Sam pointed out that the whole run had used only **47,000 tokens** for the amount of data it pulled down. In code mode he encourages the agent to write async scripts, so it can make "a thousand paginated tool calls" in parallel and hand back only the processed result, instead of going turn, tool call, turn, tool call.

**My take:** this matches what I see with clients. The fix for context bloat is rarely "drop MCP". It's making the harness decide which tools are visible and when. If your agents load every tool from every server at session start, start with progressive discovery (skills or tool search), then move bulk data work into code mode.

## Keynote: Inside AI Agents — Maarten Grootendorst, Google DeepMind

**3:04 PM | Auditorium (Ground Floor)**

After the lunch break, **Maarten Grootendorst** — Member of Technical Staff at Google DeepMind and creator of BERTopic, KeyBERT, and PolyFuzz — took the stage. Maarten's unique background spans organizational psychology, clinical psychology, and data science, which gives his technical talks a distinctly human perspective.

His keynote, *"Inside AI Agents: Offloading Human Tasks"*, explored how agentic systems are changing the way we think about workflow automation — not by replacing human judgment, but by offloading the mechanical, repetitive, and rule-bound tasks that consume human attention. He demonstrated how open-source tooling (his own libraries included) is making it possible for teams to build agents that augment rather than replace.

## The EU AI Act Thread

Two Day 1 sessions dealt with the EU AI Act, and it came up in several of my hallway conversations too.

**10:50 AM | G102 + G103 (1st Floor)**: **Mirela Takacs** (Law Office Takacs Mirela) gave *"Legal Implications Under EU Law When Deploying AI Agents"*. I didn't get to it, but an attendee with an EU law background told me about it on camera in the afternoon. What stayed with him was the idea of **drift**. A low-risk agent, such as one that schedules your calendar, can end up doing far more than it was designed to do once it's deployed. His example was an agent that starts emailing invitations to your whole address book and then links those addresses together. He also stressed the point that the [session abstract](https://agntconmcpconeu26.sched.com/event/2RB8P/legal-implications-under-eu-law-when-deploying-ai-agents-mirela-takacs-law-office-takacs-mirela) makes as well: the agent is a system, not a legal person, so the people who build and run it are the ones held accountable. The abstract's other takeaways: treat compliance as continuous monitoring rather than a one-off check, bring legal and engineering together from the design phase, keep a clear map of what the agent does, accesses and produces, and start from the AI Act before identifying any adjacent legislation the agent's functions trigger.

**3:45 PM | Auditorium (Ground Floor)**: **Steven Mih** (Action State Group, Inc.) presented *"Six Months of Proof: Independently-Verifiable Records for Agent Actions Under the EU AI Act"*. His [abstract](https://agntconmcpconeu26.sched.com/event/2RB95/six-months-of-proof-independently-verifiable-records-for-agent-actions-under-the-eu-ai-act-steven-mih-action-state-group-inc) starts from Article 12 (high-risk AI must support automatic record-keeping) and Article 19 (logs kept for at least six months), and points out that the Act can require logs to exist but can't make them trustworthy. The fix is anchoring: hash each record and write the hash to an independent, append-only transparency log (the open SCITT/COSE standards), so anyone can verify what the agent did without having to trust the operator. That's what his Agent Action Capsule project does.

![Steven Mih's live EU AI Act report showing a Week of Sep 1-6 human check, where a person blind re-graded 24 judged verdicts and each row is mapped to an AI Act article such as Art 5(1)(a), Art 26(1) or Art 50(1)](/blog/events/agntcon-mcpcon-europe-2026/steven-mih-eu-ai-act-human-check.jpg)

*From Steven Mih's demo: a weekly "human check" in which a person blind re-graded 24 verdicts from an LLM judge.*

When I photographed the demo, the screen showed a weekly **"human check"**. An LLM judge (labelled `claude-opus-4-8`) had marked each agent action against a specific article, for example Art 5(1)(a) "no manufactured pressure in the rebooking", Art 26(1) "confirm-before-write on an upgrade" and Art 50(1) "disclosure clarity, branded surface". A person had then re-graded 24 of those verdicts blind, and every row I could see read "MET / MET / agreed".

**My take:** for platform teams, these two talks fit together. The first says compliance is an architecture concern. The second shows what that means in practice: records of agent actions that an auditor can check without trusting you, plus a human sampling the AI judge's work. It's the same evidence-layer idea Traefik Labs described to me on the expo floor (more below).

## Hallway Track: Interviews From the Expo Floor

Between sessions I recorded short interviews for my show. Everything below is the guests' own account, summarised. Where a company makes a product claim, it's theirs, not mine.

**Frédéric Barthelet, CTO and co-founder of Alpic** (he gave the "Three Doors to One Tool" keynote on Day 2). He described Alpic as "the MCP hosting company", with three lines of business: the hosting platform, **Skybridge** (an open source framework for building MCP apps that run inside ChatGPT and Claude) and a services team that helps companies build on both. Travel and e-commerce brands moved first, because their customers increasingly start a journey in ChatGPT or Claude rather than in a search engine. His advice was not to bet on a single surface. MCP apps, WebMCP, CLIs and A2A are all ways to make a business usable by agents. He cited Cloudflare reporting that agent traffic had overtaken human traffic. Browser automation works as a fallback, he said, but it's slow, expensive in tokens and error-prone, so companies should build surfaces meant for agents. On jobs, he doesn't buy full automation: "only the part that we don't care about will be automated". I wrote more about Alpic's view in [AI assistants as a new business channel](/blog/alpic-ai-assistant-channel-2026/).

**Ben from Reboot** ([reboot.dev](https://reboot.dev)). Reboot is an application framework that coding agents such as Claude and Codex write full-stack apps in. Because the app is built from Reboot's own primitives, the domain objects and how they call each other can be extracted straight from the code. In his words, the spec is "literally extracted from the code", so it can't drift the way a hand-written Markdown spec does. Behaviours are written as BDD features in Cucumber/Gherkin style, mapped onto the domain objects and run as tests, including end-to-end runs with Playwright, all shown in a developer dashboard. Two things he said stood out for me. When the team let an agent add feature after feature with no human input, even inside Reboot the resulting design got complicated. And his advice to newcomers was to learn data structures, service boundaries and modular architecture rather than language syntax.

**Traefik Labs.** A member of the Traefik team walked me through the **Sovereign Trust Plane** launched that week. Traefik sits in the agent workflow as a gateway that enforces routing and security policies, observes everything through OpenTelemetry, and now writes every allow *and* deny decision to what they call an **evidence layer**. It's built to answer an auditor's three questions: what did the agent do, who authorised it (a human, or an agent acting for another agent), and can you prove it? He drew a sharp line between the two: observability is sampled and meant for troubleshooting, while evidence is complete and meant for audit. The platform is meant to work with any agent or harness. On identity he listed OAuth 2.1, token exchange (RFC 8693), ID-JAG/cross-app access and AuthZEN, and it ships as a single licensed binary that installs natively on Kubernetes. More in my [Sovereign Trust Plane post](/blog/traefik-sovereign-trust-plane-2026/).

![The FME by Safe Software booth backdrop reading FME + MCP, Get a Grip on Your Data, with a screen showing any MCP client calling MCP tools served by FME Flow's MCP server](/blog/events/agntcon-mcpcon-europe-2026/fme-mcp-booth.jpg)

*The FME by Safe Software booth: existing FME workflows exposed as MCP tools through FME Flow's MCP server.*

**Sanae Mendoza, FME by Safe Software** (she also gave the sponsored session *"Beyond the Easy 80%: Bringing Legacy, Spatial, and Locked-Down Data to MCP"*). FME is a no-code data integration platform that connects to over 500 data formats. The MCP angle is that you can build your own workflows and deploy them as MCP tools. The company is based in Vancouver, Canada.

**Avery and Theo, Valency.** They're researchers building tools for researchers: an MCP server that lets any LLM search open-access scientific papers. They only ingest open-access research. Finding papers is the easy part, they said. The work is normalising them across fields with different writing and citation norms, and scoring paper quality so the model reasons over real papers instead of whatever a web search returns. One of them, a former time-domain astronomer, said the literature work behind a paper that had taken months would have taken a day or two with the tool. Both insisted that science should stay people-driven, with humans accountable for what gets published.

**Dilip, Orkes.** Orkes offers the enterprise version of **Conductor**, the workflow orchestration engine that started as an open source project at Netflix (now Conductor OSS). Workflows can call backend APIs, agents and humans. Compared with Airflow, he said, Airflow focuses on data orchestration, while Conductor is general-purpose: customer onboarding and reconciling finance transactions as well as data pipelines.

**Dan, Runpod.** Runpod is a GPU cloud: you rent GPUs by the hour, or on enterprise contracts, and can run an open model from Hugging Face in a few clicks. According to Dan, the Blackwell range (B200 and B300) was the most requested at the time.

Two attendees gave me their takeaways too. **Marco**, a lawyer turned legal AI specialist, builds a swarm of specialised agents for legal work and compared a contract to a mid-sized GitHub repo full of cross-references: change one definition and you have to re-read every clause that depends on it. **Olivier** described WebMCP as a kind of augmented robots.txt for agents: rather than only allowing or blocking crawlers, a site chooses what to expose to them. With the EU AI Act now applying, he expects companies to need an "AI officer", the way GDPR created the data protection officer.

**My take:** the common thread across these booths was control and evidence, not raw capability: gateways that record decisions, frameworks that keep specs honest, workflow engines that survive restarts. That's the platform layer, and it's where most enterprise agent projects I see are still thin.

## What This Means for Builders

Three takeaways from Day 1 that every team shipping agentic AI should internalize:

1. **Agentic AI is not a future technology — it's a production technology.** 81% of teams building agents have them in production. The questions have shifted from "if" to "how reliable."

2. **The open standards stack is winning.** MCP at 89% adoption is just the start. The stack of protocols and standards — MCP, Skills, A2A, AGENTS.md — represents a community-driven path to interoperability that no single vendor can own.

3. **Oversight isn't overhead — it's architecture.** 66% of teams are adopting human-on-the-loop patterns. The agentic stack that wins won't be the one that removes humans, but the one that thoughtfully integrates them.

## Announcements & Product Launches

Throughout the event, the Linux Foundation and sponsors announced several key developments:

### MCP Graduates to Enterprise Infrastructure

The **Model Context Protocol (MCP)** is getting its biggest update since launch — introducing a stateless core, new extensions, stronger enterprise authorization, and a formal deprecation policy. MCP co-creator David Soria Parra discussed these changes on Day 1, noting that the protocol's move to a stateless architecture addresses the scaling concerns that have prevented adoption in enterprise environments.

### Envoy AI Gateway Becomes Agent Router, Joins AAIF

**Envoy AI Gateway** is now **Agent Router** and is joining the **Agentic AI Foundation** as a hosted project. Developers connect to models and tools through an OpenAI-compatible API and ready-to-use MCP endpoints, while platform teams manage providers, credentials, quotas, routing, and failover behind the scenes.

### Agentic AI Foundation Welcomes 57 New Members

The Foundation announced 57 new members, including major financial services players and APAC leaders. New Gold Members include **Alibaba**, **Visa**, and **Wells Fargo**, with 33 Silver and 21 Associate Members across financial services, enterprise technology, research, and global technology organizations.

### A2A Joins the Open Agentic Stack

**Agent2Agent (A2A)**, the open standard for inter-agent communication, is joining the Agentic AI Foundation as a hosted project. This fills a critical gap in the agentic stack — while MCP handles agent-to-tool connectivity, A2A standardizes agent-to-agent communication.

### MCPA Certification Launched

The Agentic AI Foundation launched the **Model Context Protocol Associate (MCPA)** certification — a foundational, vendor-neutral credential validating engineering and platform builders' understanding of MCP concepts, architecture, and implementation considerations.

### Other Sponsor Announcements

Additional product launches from sponsoring companies included:

- **Traefik Labs**: Sovereign Trust Plane for verifiable AI agent governance
- **WSO2**: Agent Manager for sovereign AI governance across enterprise agent sprawl
- **Grape Up**: Aiboostr — an open-source AI governance and orchestration platform with EU AI Act compliance and private LLM support
- **Omnys**: Joined as Gold Sponsor, showcasing the OMNYS AI Platform with native MCP support
- **AgentCat**: Launched the first Agent Experience (AX) platform combining agent analytics, goal detection, and session replay
