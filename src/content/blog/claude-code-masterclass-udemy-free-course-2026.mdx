After months of using Claude Code in production across multiple projects, I kept seeing the same pattern: developers install it, type a vague prompt, get mediocre output, and conclude AI coding tools are overhyped.

The problem is never the tool. It is always the workflow.

## What You Will Learn

The course follows one loop through every module: **Plan → Implement → Test → Review → Commit**.

### Section 1: Introduction

Meet your instructor and understand the project-driven format. One mindset ties everything together: Claude Code is a sharp junior engineer you direct and review.

### Section 2: Foundations — Setup, Prompting and Brain Files

- **Setup and AI-First Mindset** — Install Claude Code on macOS, Linux, or Windows (WSL2). Pick the right model: Sonnet for implementation, Opus for design, Haiku for bulk tasks.
- **Prompting Like a Tech Lead** — Learn the GCOE framework: Goal, Constraints, Output format, Examples. Every constraint deletes one wrong guess Claude could make.
- **CLAUDE.md Brain Files** — Stop re-explaining your stack every prompt. Author a behavior file with five sections: Stack, Conventions, Commands, Do-not, Glossary. Apply the "trim test" to keep it lean.

### Section 3: Create Code That Works

- **Best-of-N Selection** — The first answer is rarely the best. Generate independent candidates, score them on a rubric where correctness gates and simplicity breaks ties, then ship the winner with evidence.
- **Testing and Debugging** — Generate real test suites covering error paths and boundaries. Then use the "stranger's PR" self-review prompt to flip Claude from cheerleader to critic.
- **Git Workflows** — Never let Claude push to main. Branch first, split into atomic Conventional Commits, and generate PR descriptions from the actual diff — never from your prompt.

### Section 4: Multimodal

Feed Claude screenshots of broken UIs, design mockups, or architecture diagrams and turn pixels into code. Learn when a picture is worth a thousand tokens.
