## GitHub Copilot Dev Days Amsterdam

On May 6, 2026, the **GitHub Copilot Dev Days** community meetup brought together developers at [TrueFullstaq](https://truefullstaq.com/), Keienbergweg 100, Amsterdam for an evening focused on AI-assisted coding with GitHub Copilot.

The event explored practical workflows and real engineering use cases:

- 🤖 GitHub Copilot in day-to-day development
- 🔍 AI-assisted code reviews
- 🚨 Copilot-powered incident triage
- ⚙️ Developer productivity and modern engineering workflows

## Agentic SDLC in Action

[Burak Unuvar](https://www.linkedin.com/in/burakunuvar/) live-demonstrated **Agentic SDLC in action** — a fleet of AI agents collaborating across multiple surfaces to handle the full software development lifecycle. This goes beyond simple code completion: agents handling planning, implementation, testing, and deployment in coordinated workflows.

![Projected title slide reading Agentic SDLC with GitHub Copilot](/blog/events/github-copilot-dev-days-amsterdam-2026/agentic-sdlc-title-slide.jpg)

*The opening slide of the Agentic SDLC session.*

The session was split into parts: a later slide is titled "GHCP in Action - Part 3 - Fleet", and one slide announced "An incident has happened" before the talk moved to a building-blocks view for handling it. That slide asked "What do we need?" and answered with five boxes in a row, Trigger, Runtime, Harness, Model and Context, Tools & MCP, all sitting above a "Security Measures" bar.

![Slide titled What do we need? with five steps: Trigger, Runtime, Harness, Model, Context Tools and MCP, over a Security Measures bar](/blog/events/github-copilot-dev-days-amsterdam-2026/what-do-we-need-slide.jpg)

*"What do we need?": trigger, runtime, harness, model and context with tools and MCP, wrapped in security measures.*

My take: this is a useful checklist for any agent that reacts to an event such as an incident. If you cannot say what the trigger, runtime and harness are, and where the security measures sit, you do not yet have an agent, only a prompt.

## Agentic Coding Workflows

[Radek Kowalski](https://www.linkedin.com/in/radek-kowalski/) presented on **agentic coding** and the workflow his team uses for their projects — showing how teams are already integrating AI agents into their daily engineering processes, not as a future vision but as current practice.

The talk was titled "AI-augmented teams: The 2026 Collaboration Blueprint" on the opening slide. Later slides covered "AI Coding Maturity Stages" and "The 5 levels of agentic development". One slide drew the interaction between a person and an agent as a sequence: the person states intent, the agent replies with its interpretation, they reach alignment and a plan, the person approves, and only then does the agent code, build and test before opening a pull request and receiving feedback.

![Slide showing a person and an AI agent exchanging intent, interpretation, alignment, plan and approval, followed by the agent's code, build, test, PR and feedback steps](/blog/events/github-copilot-dev-days-amsterdam-2026/human-agent-loop-slide.jpg)

*The human and agent interaction sequence: everything up to approval is a conversation, everything after it is the agent's loop.*

A later adoption slide, tagged "official: sharing quick wins, first policies emerge", listed four actions for teams:

![Slide listing four adoption actions: make AI use explicit and encouraged, introduce guardrails, enable knowledge sharing and manage the expectations](/blog/events/github-copilot-dev-days-amsterdam-2026/make-ai-use-explicit-slide.jpg)

*Four actions for adopting AI in a team, as listed on the slide.*

- **Make AI use explicit and encouraged:** move away from shadow usage, empower the champions and bring sceptics on board.
- **Introduce guardrails:** code review expectations, data access rules and autonomy boundaries.
- **Enable knowledge sharing:** guilds, communication channels and air time in company ceremonies.
- **Manage the expectations:** discuss the costs, the trade-offs and the ROI with the leadership and the stakeholders.

## The Big Question

The session sparked what [Paco Bernabé](https://www.linkedin.com/in/pacobernab%C3%A9/) called "the question of the night":

> *"If the role of engineers will change to supervisors of the code generated by AI, how will engineers be able to review if they don't have coding experience?"*

This is the fundamental tension of the AI-assisted coding era. As tools like GitHub Copilot and [Claude Code](/blog/claude-code-bootcamp-packt-certification-2026/) handle more of the implementation, the skill set shifts from writing code to understanding systems, evaluating quality, and maintaining architectural integrity. The answer likely involves a new kind of literacy — not syntax fluency, but systems thinking and quality judgment.
