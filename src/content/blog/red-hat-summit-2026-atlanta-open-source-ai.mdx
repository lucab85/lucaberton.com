## InstructLab: SDG Hub and Training Hub

![InstructLab SDG Hub and Training Hub — Scan Repos, Start Contributing](/blog/events/rh-summit-2026-instructlab-repos.jpg)

The InstructLab team presented two key components for community contribution: the **SDG Hub** (Synthetic Data Generation) and the **Training Hub**. Both repositories are open source and actively seeking contributors — the stage showed QR codes linking directly to the GitHub repos.

![Customer Success Story — German public sector with Red Hat AI](/blog/events/rh-summit-2026-customer-story.jpg)

A powerful customer success story from a **German public sector** deployment (Atos and Red Hat partnership). The challenge: analyzing vast unstructured social media data for 14 distinct features with 100% valid JSON extraction and precise violence detection. The solution used a "Teacher-Student" methodology with SDG Hub — training Phi-4 Mini (1B), Qwen 2.5 (1.5B), and Qwen 2.5 (7B) models using SFT and Orthogonal Subspace Fine-Tuning (OSFT) via OpenShift AI. The results: **Qwen 2.5 7B outperformed GPT-4.1** with a detailed prompt (30.8 vs 30.5 pts), and Phi-4 Mini 1B improved JSON validity from 1% to 99% after fine-tuning. The entire pipeline ran on just **3x NVIDIA L40 GPUs**.

![Training Hub — Unified API for modern LLM post-training](/blog/events/rh-summit-2026-training-hub.jpg)

The **Training Hub** provides a unified API surface for modern LLM post-training. It supports supervised fine-tuning (SFT), LoRA/QLoRA parameter-efficient tuning, OSFT, and Lora-GRPO — all through the same Python API. Native integration with MLFlow for experiment tracking and the Kubeflow Training Operator for Kubernetes-scale training. Install it with `pip install training-hub[lora,grpo]`.

![Live coding demo of Training Hub at Red Hat Summit 2026](/blog/events/rh-summit-2026-live-coding.jpg)

The live coding demo walked through loading a HuggingFace dataset, generating 13,222 training examples via SDG, and running OSFT continual learning on the Qwen 2.5 1.5B Instruct model — all in a Jupyter notebook.

![MLFlow model metrics — OSFT Qwen2.5 1.5B training](/blog/events/rh-summit-2026-mlflow-metrics.jpg)

Real-time MLFlow experiment tracking showing model metrics for the `osft-Qwen2.5-1.5B-Instruct-tablegpt` training run: avg_loss_backward, avg_time_per_minibatch, and batch_num_loss_counted_tokens across 50 training steps.

![Red Hat Summit 2026 demo stage with InstructLab presentation](/blog/events/rh-summit-2026-demo-stage.jpg)

The demo stage at Red Hat Summit — a purpose-built theater with headphone listening stations. The InstructLab demo covered an openly available DOTS notebook for continual learning, showing how off-the-shelf limitations can be overcome with targeted fine-tuning while preserving general capability.

### Madhu, Red Hat: Event-Driven Ansible as an Automated Switchboard

![Madhu, Red Hat, demonstrating Event-Driven Ansible at the Ansible booth at Red Hat Summit 2026](/blog/events/rh-summit-2026-madhu-eda.jpg)

At the Ansible booth, **Madhu** from Red Hat unpacked [Event-Driven Ansible](/blog/event-driven-ansible-reactive-automation/) (EDA) for me — described as an automated switchboard for your automation stack. EDA listens for events from the outside world and routes each one to the right job template in real time. Rulebooks let you combine single or multiple event conditions with temporal, sliding time windows — think SLA logic: "if two events don't both fire within 10 minutes, raise an alert." Underneath, EDA runs on a rules engine built for business process management, enabling complex multi-event correlation. In version 2.7, Red Hat added event persistence: events are stored so nothing is lost on a crash, and in-flight controller jobs resume right where they left off. That persistence work sets the stage for full high availability with active-passive failover, coming next.
