## vLLM: Two Core Concepts

The talk structured vLLM around two pillars:

1. **Inference Optimizations** — Making individual model serving faster and leaner
2. **Distributed Inference** — Scaling across multiple GPUs and nodes

## KV Cache: The Foundation of Fast Inference

Every transformer token generation requires attending to all previous tokens. Without optimization, this means recomputing the full attention matrix every step.

**KV Cache** stores the Key and Value tensors from previous tokens, avoiding redundant computation for the prefix. This is the single most impactful optimization for autoregressive generation.

### Static vs Continuous Batching

- **Static batching**: All sequences in a batch must wait for the longest to complete
- **Continuous batching**: Fill empty slots with new sequences as others finish — dramatically improving throughput

vLLM implements continuous batching natively, ensuring GPU utilization stays high even with variable-length requests.

## Quantization: Fit More, Lose Almost Nothing

### Supported Formats

| Format | Description |
|--------|-------------|
| W4A16 | 4-bit weights, 16-bit activations |
| W8A16 | 8-bit weights, 16-bit activations |
| W8A8-INT8 | 8-bit weights and activations (integer) |
| W8A8-FP8 | 8-bit weights and activations (floating point) |
| 2:4 sparse | Structured sparsity |

### Algorithms

- **GPTQ/AWQ** — Post-training weight quantization
- **SmoothQuant** — Activation-aware quantization
- **SparseGPT** — Structured pruning
- **RTN** — Round-to-nearest baseline

### Hardware Support

Multi-accelerator from day one:
- NVIDIA GPUs
- AMD Instinct
- Google TPUs
- Intel CPUs

### Benchmark: DeepSeek-R1-0528 Quantized (W4A16)

Red Hat (Neural Magic) quantized the full DeepSeek-R1-0528 model to W4A16:

- **Parameters**: 67B (quantized from 671B MoE active params)
- **Architecture**: DeepseekV3ForCausalLM
- **Certified**: RHOAI 2.24/2.21

**Quality retention is remarkable:**

| Benchmark | Quantized | Full Precision | Delta |
|-----------|-----------|----------------|-------|
| AIME 2024 | 87.33 | 88.66 | -1.5% |
| MATH-500 | 97.40 | 97.52 | -0.1% |
| GPQA Diamond | 80.61 | 79.65 | +1.2% |
| Reasoning Avg | 88.45 | 88.61 | -0.2% |

Barely any quality loss — and on GPQA Diamond, the quantized model actually *outperforms* full precision.

## Real-World Example: Llama-4-Scout-17B-16E

This example drives the point home:

- **Full precision**: 640 GiB
- **W4A16 quantized**: 170 GiB (**75% reduction**)
- **Hardware needed**: 4x 48 GiB GPUs
- **Context window**: 500K tokens (vs 20K unquantized)
- **Precision loss**: Only 1.5%

The quantized version gives you 25x more context window with 75% less memory and negligible quality impact.

The speaker showed Open LLM Leaderboard results demonstrating ~99% quality recovery after quantization across all major benchmarks. Red Hat's $400M investment in Neural Magic / vLLM is paying off in production-ready quantized models.

## Distributed Inference: Scaling Beyond One GPU

### Why Distribute?

DeepSeek V3 (671B parameters) needs **at least 16 H100 GPUs**. Most enterprise models today cannot fit on a single device.

### Progression Path

1. **Single Device** — One GPU, model fits in memory
2. **Single Host, Multi-Device** — Multiple GPUs on one machine (NVLink)
3. **Multi-Host, Multi-Device** — Multiple machines, multiple GPUs each

### Parallelism Strategies

- **Tensor Parallelism (TP)** — Split layers across GPUs
- **Pipeline Parallelism (PP)** — Split model stages across GPUs
- **Expert Parallelism (EP)** — For MoE models, distribute experts
- **Data Parallelism (DP)** — Replicate model, split batches
- **Disaggregated Serving** — Separate prefill, decode, KV cache

### Tensor Parallelism in Practice

Model Sharding + Parallel Execution Engine running prefill, decoding, and KV cache operations in parallel across devices.

## The Challenge with Monolithic LLM Inference

The speaker articulated why vLLM alone is not enough for enterprise scale:

- Monolithic containers prevent easy observability
- Autoscaling based on CPU/memory misses token demand
- Cannot scale individual components (prefill vs decode)
- Hard to meet real-world SLOs

This sets up the case for **llm-d** — covered in my [companion post on Red Hat AI Model-as-a-Service](/blog/red-hat-ai-model-as-a-service-llm-d-maas-platform-2026/).

## Key Takeaways

1. **Quantization is production-ready** — W4A16 gives 75% memory savings with under 2% quality loss
2. **vLLM supports all major accelerators** — NVIDIA, AMD, Google TPU, Intel
3. **Distributed inference is necessary** — Modern models simply do not fit on one GPU
4. **"vLLM combines them all together"** — Prefix caching + Prefill + FP8 KV Cache in one engine
5. **Red Hat's $400M Neural Magic investment** delivers production-certified quantized models
